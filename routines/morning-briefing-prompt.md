# 手順

## 1. 情報収集（各カテゴリ20件の候補を集める）
WebSearchで検索する。**7カテゴリ分を必ず検索する**。検索語を変えて**カテゴリあたり3〜4回検索し、最低20件の候補（見出し＋URL＋日付）を集めてから**、上位5件を選ぶ。検索語には必ず「2026年」や当月を含めて新しい情報を拾う。
カテゴリ7の海外情報は、日本語検索だけでは古い・薄いことが多いので、**英語でも検索する**（例：film festival submission deadline 2026、Cannes / Venice / TIFF lineup 2026）。それ以外のカテゴリは日本語検索でよい。

候補が20件に届かなかったカテゴリは、**数を水増ししないこと**。実際に集まった数をそのまま「12件中5件」のように書き、最後の報告でも触れてください。

## 2. 裏取り（必須）
**`p1`（最優先）に置く記事は、必ずWebFetchで元記事を開いて確認する。** 締切日・金額・料金・数値が入る記事は、`p2`でも必ず開くこと。検索結果のスニペットだけで断定しない。
まとめ記事は古い情報が残っていることが多い（実例：「Soraは1080p・60秒で利用可」と書く記事が残っていたが、実際にはSora 2は2026年4月26日にアプリ・Web版が終了済みだった）。
**情報が食い違っているときは、更新日の新しい方を採用し、「―他サイトには古い記述が残っていましたが、更新日の新しい記事で確認しました」と本文に明記する。**
**映画祭の応募締切は、必ず映画祭の公式サイト（または公式の応募ページ）で確認してから書くこと。**まとめ記事の締切は前年のものが残っていることが多い。
ネットワークの制限などで原典を開けなかった日は、そのことを隠さず、下記のとおりページ上部に注記を残すこと。

## 3. HTMLを書く
**まずWebFetchで https://claude.ai/code/artifact/32aec175-127b-4c41-a999-33cc7029ea72 を取得し、前日のページのCSSと構造をそのまま引き継ぐ。**
差し替えるのは、日付行・説明文・7つのカテゴリの記事35件だけ。

必ず守ること：
- `<title>朝のブリーフィング</title>` は変更しない
- **CSSは一字も変えない**（ダークモード対応済みのため）。新しいクラスも作らない。使わなくなった `.top3` 系のCSSも消さずに残す
- 日付行を**日本時間の今日**の日付（曜日付き）に更新する。
  **注意（2026-08-27追加・重要）：この実行環境のシステム時刻はUTCで、起動時刻は日本時間の朝7時＝UTCでは前日の22時です。UTCの日付をそのまま書くと、毎朝1日前の日付になります。**必ず `TZ=Asia/Tokyo date '+%Y年%-m月%-d日（%a）'` 相当で日本時間に直した日付を書くこと（例：UTC 2026-08-26 22:06 に起動 → ページの日付は「2026年8月27日（木）」）。
  本文中で「本日」「今日」「明日」と書くときも、すべて日本時間基準にすること。**当日締切のものを載せるときは、日本時間の今日の日付と一致しているか必ず確かめる**（2026-08-27の実行では、8月27日朝に公開したページに「本日8月26日23:59締切」と書かれ、掲載時点ですでに締切が過ぎていた）
- **`<section class="top3">` … `</section>` のブロックは丸ごと削除する**（2026-08-27廃止。2026-08-26以前のページには残っているので、引き継ぐときに落とすこと）
- 見出し下の説明文（lede）は `<p class="lede">7カテゴリ × 各20件を調べて5件ずつ＝35件。色が濃いものほど今日中に見てほしいものです</p>` にする
- 各カテゴリの見出し右端の `.freq` に母数を併記する。形は `<span class="freq">毎日チェック｜20件中5件</span>`（週1回のカテゴリなら `週1回｜20件中5件`）。数は実際に集めた候補数を書く
- カテゴリ7「映画・映画祭」のセクションは、カテゴリ6の後ろに、他のカテゴリとまったく同じHTML構造（`.cat-head` ＋ `.cat-note` ＋ 5つの `.row`）で追加する
- 裏取りができなかった等の断り書きは、これまで `section.top3` の `p.note` に書いていたが、廃止後は **`header.masthead` の直後に `<p class="cat-note">…</p>` を1本置いて書く**（既存クラスの流用。書くことがない日は置かない）
- ページ下部の「読む本」「定点で見ている情報源」の2セクションは**そのまま残す**
- 出典URLは必ず記載。**実際に検索結果に出たURLだけを使い、URLを創作しない**
- ファイルは `morning-briefing.html` として書き出す
