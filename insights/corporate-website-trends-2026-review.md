## 1. 記事の要点

### 大前提

> コーポレートサイトは「静的な会社案内」から、動的な**ビジネスインフラ**へ完全に移行した。
> **美しいだけのサイトは、資産ではなく負債になる。**

背景として、人手不足と、B2Bの購買行動が完全に非接触化したこと（＝営業に会う前に、サイトだけで比較・選別が終わっている）が挙げられています。

### 5つの構造トレンド

| # | トレンド | 一言でいうと |
|---|---|---|
| 1 | **AEO / Schema**（AIに「選ばれる」ための構造改革） | 人間ではなく**AIに読ませる**ためにサイトを組み直す |
| 2 | **Evidence / Raw Video**（動画による証明） | 作り込んだ映像より**生の映像**のほうが信じられる |
| 3 | **Transparency / Self-Service**（情報の透明化） | **問い合わせさせない**。サイトだけで判断させる |
| 4 | **Speed as Trust**（爆速表示による信頼構築） | 表示速度が**そのまま会社の技術力と誠実さ**として読まれる |
| 5 | **Inclusive Design**（読みやすさへの配慮） | 読む負担を減らすこと自体が配慮の証明 |

**5つに共通する思想：ユーザーの「見えないストレス」を排除する。**

### 各トレンドの中身

**1. AEO / Schema — AIに「選ばれる」ための構造改革**
Schema.org（構造化データ）を「サイトの裏側に書いておく共通言語」と位置づけ、これがAI側の学習・理解効率を劇的に上げる、という話。SEO（検索順位を取りにいく）から**AEO＝Answer Engine Optimization（AIの回答に引用される）**へ主戦場が移った、という整理です。

**2. Evidence / Raw Video — 動画による「証明」**
記事中の数字：

- 日常環境（オフィスや自宅）で撮った映像は、**プロのスタジオ撮影に比べて信頼スコアが41%高い**
- **86%の消費者**が、作り込まれたインフルエンサー投稿より「本物のユーザー生成コンテンツ」を信頼する

B2Bの文脈でも、**「生々しさ」「実在感」が真実性の証明として評価される**段階に入った、と。あわせて「**笑顔の外国人ビジネスパーソンのストックフォトは使うな**」（グローバル感ではなく“不信”のシグナルになる）と明言されています。

**3. Transparency / Self-Service — 情報の透明化**
料金・条件・プロセスを出し渋ると、それ自体が離脱理由になる。**問い合わせという行為そのものがユーザーのストレス**なので、問い合わせずに済む状態を作る。

**4. Speed as Trust — 爆速表示による信頼構築**
2026年、**スマホでの快適さは「その会社の技術力と誠実さ」として評価される**。重厚なデザインより爆速表示が信頼を生む。Core Web Vitals（Webに関する主な指標）をクリアするのはSEOのためだけではなく、「不安定な電波状況でもストレスなく情報を届ける」という配慮が、ビジネスパートナーとしての信頼性を無言で証明する、という論。
具体策として、**重要な情報をPDFで置かず、スマホで読めるHTMLページに変換する**（通信量を減らす）ことが挙げられています。

**5. Inclusive Design — 読みやすさへの配慮**
文字サイズ・行間・コントラストなど、読む負担を下げる設計。装飾ではなく前提条件として扱う。

ここから見える課題：

1. **全ページのURLが日本語スラッグ**（`%E4%BC%9A...`）。共有すると文字化けした長いURLになり、メール・SNS・提案書に貼ったときに信用を落とす。AIやクローラにとっても意味が取りにくい。
2. **一部ページが `http://` でインデックスされている**。HTTPS常時化・301リダイレクトが徹底されていない可能性。**【要実機確認】** ブラウザで鍵マークが出るか、`http://` が `https://` に飛ぶか確認が必要。
3. **WordPressのauthorアーカイブが公開・インデックスされ、ページタイトルに `info@create-links.jp` が出ている。** 迷惑メールの回収対象になる。閉じるべき。
4. **`/sitemap/` のタイトルが「自社作品 映画」** ＝ ページタイトルの管理ができていない。タイトルはAIにも人にも最初に読まれる部分。
5. **料金・制作フロー・納期・対応範囲を出しているページが見当たらない。** 進行中の「動画制作受託の営業強化」に対して、これは**いちばん痛い穴**（トレンド3に真正面から反する）。
6. **「映像制作」ページはあるが、受注実績を証拠として並べた実績ページが見当たらない。** **【要実機確認】**
7. **動画制作会社なのに、サイト上で動画による証明ができているか不明。** **【要実機確認】** ここが最大の伸びしろ（後述）。

## 3. うちならではの勝ち筋（ここだけは読んでください）

### ① 「動画制作会社なのに、動画で証明していない」を潰す

記事の**トレンド2は、うちにとってだけコストがほぼゼロ**です。他社は「生の動画を撮る」ところから外注費が発生しますが、うちは**それが本業**。しかも記事が言っているのは「**作り込むな、日常環境で撮れ（信頼スコア41%高）**」なので、**編集工数すらかけないほうが効く**。

置くべき生素材（各30〜90秒、スマホ撮影可）：

- 撮影現場のオフショット（機材セッティング、モニターチェック中の様子）
- せいじさんが「この案件はこう考えて撮りました」と一人で喋るだけの解説
- 編集画面のスクリーンキャプチャ（AIガタリの生成過程そのもの）
- クライアントの一言コメント（許可が取れたものだけ）

**これは「サイト制作」ではなく「今月の撮影ついでに回す」で足ります。**

### ② タレント・映画は、Schemaと相性が異常にいい

トレンド1（AEO）は抽象的に聞こえますが、うちの事業には**そのまま当てはまる型**があります。

| 対象 | 使うSchema | AIに何と答えさせたいか |
|---|---|---|
| 所属タレント各人 | `Person` | 「〇〇さんの所属事務所は？」→ CREATE-Links |
| 映画「虹、結」等の自社作品 | `Movie` | 「虹、結 監督」→ 大原誠弍／製作 CREATE-Links |
| 大原誠弍さん個人 | `Person`（監督・脚本・ナレーター・講師を職能として明記） | 「映画監督 大原誠弍」への回答に引用される |
| 会社 | `Organization` | 「東京 映画製作会社」系の回答候補に入る |
| 受託サービス | `Service` ＋ `Offer` | 「企業VP 制作会社 東京 相場」への回答に入る |

**タレントマネジメント事業にとって、これは営業ツールそのものです。** タレントさんの名前がAIに聞かれたときに事務所名が一緒に返るかどうかは、所属タレントへの説明材料にも、新規所属の勧誘材料にもなります。

### ③ 「問い合わせさせない」＝ 受託営業の工数削減

トレンド3は、せいじさんの時間を直接買い戻す施策です。料金レンジ・制作フロー・納期・NG条件をサイトに出せば、**予算が合わない問い合わせが減り、その分の対応時間が消える**。年商5億の目標に対して必要なのは問い合わせ件数ではなく、**成約する問い合わせの比率**です。

出す情報の最低ライン（レンジで構いません）：

- 企業VP：〇〇万円〜／2〜4週間
- YouTube運用：月〇〇万円〜／最低〇ヶ月
- 撮影のみ：〇〇万円〜（1日／カメラ〇台）
- 対応外（＝受けない仕事）も書く ← ここを書くと信用が跳ねます

## 5. リニューアル発注書にそのまま貼れる文言

```
【必須要件】
1. URLは英数字スラッグとし、既存の日本語URLからは全件301リダイレクトを設定すること。
2. 構造化データ（Schema.org / JSON-LD）を実装すること。対象：Organization、
   Person（代表・所属タレント各人）、Movie（自社製作作品）、Service（受託サービス）。
   実装後、Google のリッチリザルトテストでエラーゼロであることを検収条件とする。
3. Core Web Vitals をモバイル実測で以下を満たすこと。
   LCP 2.5秒以内 / CLS 0.1未満 / INP 200ms未満。検収時に PageSpeed Insights の
   モバイルスコアを提出すること。
4. 本文文字サイズ16px以上、行間1.7以上、文字と背景のコントラスト比4.5:1以上。
5. 主要な情報はPDFではなくHTMLページで提供すること。PDFは補助的なダウンロードに留める。
6. 動画は自社撮影素材を前提とし、ストックフォト・ストック映像は使用しないこと。
7. HTTPS常時接続。http:// へのアクセスは https:// へ301でリダイレクトすること。
8. WordPressのauthorアーカイブ、日付アーカイブは noindex とすること。
```
