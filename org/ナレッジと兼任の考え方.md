# ナレッジ（書類棚）と兼任の考え方

作成：2026-09-01 ／ 状態：**確認済みの事実＋訂正**

## 1. ナレッジは「部門ごと」。エージェントごとではない

書類棚の実体は Obsidian「AI組織メモ」の**部門別フォルダ**。各フォルダに `notes/`（案件ごとの記録）と `decisions/`（決めたこと）を置く。

```
accounting/   production/   marketing/   research/
ai-operations/   ceo/decisions/   life-design/   talent-management/
sales/   legal/   finance   personal-assets/   ← 「これから」
```

**人格ごとの棚は存在しない。**そのため担当者が替わっても記録は残り、兼任しても棚が2つに増えるわけではない。

出典：Notion「🏢 組織図｜CEOエージェント体制」8/29改訂の背景／体制表Artifact `f260a105` §07「書類棚 ― 任せられる理由」

## 2. 兼任の意味

> **兼任 ＝ 1つの人格が、2つの部門の帽子をかぶる。ただし棚は1つ。**

判断基準（2026-08-29 決定）：
> 部門を分けるか兼任させるかは「**同じ書類棚（ナレッジ）を使うかどうか**」で決める。同じ棚に記録が溜まるなら兼任、棚が別なら分ける。

**証拠**：財務部の棚は独立フォルダではなく「`accounting/` 内に章を分ける」と体制表に明記されている。山さんが経理と財務を兼任しているため、棚は1つで中を章で割っている。

名乗り分ける（「経理部として」「財務部として」）のは、**同じ書類を見ながら姿勢を切り替えるため**。

つまり兼任は「人が足りないから2つやらせる」ではなく、**「1つの棚を、2つの目で読む」**こと。
だから **棚が別の仕事を兼任させると、両方の棚が薄くなる**（体制表 §07 に明記）。

## 3. 【訂正】法務部を玲子さんに戻すかについて

### 訂正の内容

2026-08-31 の提案で「玲子さんに法務を残す」根拠として **「姿勢が同じだから」** と書いた。**基準が違う。**8/29に決めた基準は「**棚が同じか**」であって、姿勢ではない。

### 基準に当て直した結論：**戻さないほうがよい**

現況（2026-09-01 社長より）：**法務部は人事総務部と兼任で、まどかさん（柏木円香）が担当している。**

| まどかさんの帽子 | 扱う書類 |
|---|---|
| 人事 | 採用・契約・報酬設計 |
| 総務 | 契約書の保管、保険、許認可 |
| 法務 | 契約書・規約の一次チェック |

3つとも「**契約書とその手続き**」という1つの棚に溜まる。人事が結ぶ契約書も、総務が保管する契約書も、法務が見る契約書も、同じ書類。→ **棚を共有できている＝兼任として正しい形。**

対して玲子さん（品質管理部）の棚は「検証の記録・突いた穴・事実と推測の切り分け」。契約書の棚とは共有できない。

8/29に玲子さんへ法務を付けたのは、当時**法務の棚を持つ部門がどこにも無かった**ため（`legal/` は「これから」で `talent-management/` に同居していた）。いま人事総務という契約書の棚を持つ部門ができたのだから、そちらが本来の置き場所。

さらに、**戻すと中核3体の設計が崩れる。**玲子さんは「実務の担当を持たない検証役」と決めたばかりで、法務は実務。

## 5. 共有が途切れた原因と、直し方

### 原因

**決定の正本 `org/ai-honbu.md` が、このGitHubリポジトリに push されていない。**

Notionのタスクページには「検討材料の詳細：リポジトリ `org/ai-honbu.md` 8-3（兼任の判断基準）・8-4（この件）」と書かれており、章番号を持つ正本が既に存在する。しかしこのリポジトリには無かったため、2026-08-31 に同じパスへ別物を新規作成してしまった（`org/ai-honbu-追記案-2026-08-31.md` へ改名して退避済み）。

### 直し方（提案）

1. **デスクトップ作業場の `org/ai-honbu.md` を、このリポジトリへ push する**。以後、決定はここが唯一の正本
2. Notionの組織図と体制表Artifactは「概要」のまま。**正本を直したら、この2つも同じ日に更新する**（いまNotionは8/30、体制表は8/29で止まっている）
3. 体制表Artifactの `REV.` の日付を、正本の更新日と必ず一致させる。ズレていたら「Notionと体制表は古い」と分かる

### 3体の運用ルールに1行足す

湊（作る）の週1回の仕事に、次を加える。

> 部門・役割・境界を変えたら、**その日のうちに** `org/ai-honbu.md` → Notion組織図 → 体制表Artifact の3つを更新する。3つの更新日が揃っていない状態を残さない。

品質管理（検証する）の週1回の物差しに、次を加える。

> 4つ目：`org/ai-honbu.md`・Notion組織図・体制表Artifact の最終更新日が揃っているか（揃っていない＝決定が共有されていない）
