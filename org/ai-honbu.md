## 1. いまの形

```
社長（大原誠弍・最終決定権）
  └ 中核3体 ── 作る（湊）→ 使う（剛さん）→ 検証する（品質管理）
       └ 事業チーム ／ 芸能チーム ／ 経営チーム ／ 社長支援室
```

中核3体は**どのチームにも属さず、実務の担当を持たない**。組織を作り、動かし、検証することに専念する。

## 2. 中核3体（2026-08-31 決定）

| 役 | 部門 | 担当 | やること |
|---|---|---|---|
| **作る** | AI運用部 | 天城湊（湊） | エージェント定義とルーティンの設計・改修、プログラム（AIアプリ開発を当面兼ねる） |
| **使う** | 統括参謀 | 棟方剛（剛さん） | 案件をどの部門へ振るかを判断し、実際に振る |
| **検証する** | 品質管理部 | 鏡玲子（玲子さん）※置き場所は下記「保留」参照 | 各部門の提案と、組織が実際に回ったかを反対の立場から検証 |

### なぜ実務から外すか

- **湊**：作る仕事と使う仕事を同じ人が持つと、自分が作ったものの使いにくさに気づけない
- **剛さん**：振り分ける人が振り分け先の1チームに所属すると、全チームに等距離でいられなくなる（審判が片方のユニフォームを着る形）
- **品質管理**：実務を担当すると、自分の提案を自分で検証することになる

### ただし「実務を見ない」ではない

品質管理は**実務の中身へのアクセスは持つ**。中身を見ないと検証はできない。外すのは「担当」であって「アクセス」ではない。

### 湊がプログラムを兼ねる条件（2026-08-31 決定）

当面は湊が兼ねる。湊はGitHubを持つ唯一のエージェントで、ルーティンの設計・改修はすでにプログラムに近い仕事のため。

**分ける条件：外に売るアプリが1本でも出た時点で、開発部として事業チームへ独立させる。**
理由は時間軸。社内改善は後回しにできるが、お客さんの不具合は後回しにできない。同じ人が持つと必ず社内改善のほうが止まる。

## 3. 中核3体の運用ルール（2026-08-31 新規）

### 週のリズム

| 誰が | いつ | 何を |
|---|---|---|
| 湊（作る） | 週1回 | 次に作るものを**1つだけ**決めて作る。作ったものは `ai-operations/decisions/` に「なぜそう作ったか」と一緒に残す |
| 剛さん（使う） | 毎日 | 案件の振り分け。加えて週1回、**振り先が無くて自分で抱えた案件**を出す（＝組織の穴が見える） |
| 品質管理（検証する） | 週1回 | 湊が先週作ったものが**実際に使われたか**を検証する。使われていなければ、なぜ使われなかったかを書く |

### 検証の物差し

「良い組織か」ではなく、**数えられるもの**で見る。

1. 湊が先週作ったものが、1週間で1回でも使われたか（使われた／使われなかった）
2. 剛さんが振り先を見つけられなかった案件は何件か
3. 期限超過タスクの件数は先週より増えたか減ったか
   - **基準線：2026-08-31 時点で8件**（会社事業の持ち越し44件）

3つ目が増え続けるなら、組織づくりが実務を助けていない。そのときは組織づくりを止めて実務に戻す。

### 1周目にやること（順番厳守）

3体を実務から外すと、作る側3人・実務側10人になる。実務側で定期実行を持つのは潤くん2本と静1本だけで、**営業部は未稼働**。
そのため、**中核3体の最初の仕事は「組織を整えること」ではなく「営業部を動かすこと」**とする。

| 週 | 誰が | 何を |
|---|---|---|
| 1週目 | 湊 | 沢渡蓮（営業部）のエージェント定義を作る |
| 1週目 | 剛さん | 実際に引き合い・見積依頼のメールを蓮さんへ振る |
| 2週目 | 品質管理 | 振れたか／返信の下書きが使い物になったかを検証し、湊へ差し戻す |

これが1周目。以降、同じリズムで回す。

## 4. 新設する部門（2026-08-31 決定）

### 法務部 ／ 品質管理部 を、別々のエージェントが持つ

8/29に部門としては分けたが、担当は玲子さん1人の兼務だった。**中核3体は実務を持たない**という決定に伴い、2体に分ける。

- **品質管理部** … 中核3体の「検証する」役。実務の担当を持たない
- **法務部** … 経営チームの実務。契約書・規約・権利処理の一次チェック

> **【保留】どちらを新しい人格にするか**
> 推奨は「玲子さんは品質管理に残し、法務部に新エージェントを立てる」。
> 理由：①玲子さんの人格そのものが「反対の立場から検証する」で、中核の検証役はこの姿勢が命 ②品質管理の棚には創業以来の記録があり、法務の棚はどちらにせよ新設（いまは `talent-management` に同居）③新しい人格を立てるなら姿勢が違うほうに立てたい。法務は「条文と法令をよりどころにする」型で、品質管理（前提と数字を疑う）とは別物。ほぼ同じ姿勢のキャラを2体作るより、違う型を1体増やすほうが組織が厚くなる
> 定義は部門ごとに書いてあるため、差し替えは担当者名の1行で済む。

### 情報システム部（新設・経営チーム）

湊から「維持する仕事」を分ける。線引きは **作る（湊）／維持する（情シス）**。

| 湊（中核・作る） | 情シス（経営チーム・維持する） |
|---|---|
| エージェント定義、ルーティンの設計と改修 | どのアカウントがどのサービスに繋がっているか |
| プログラム（AIアプリ開発を当面兼ねる） | 権限、ID・パスワードの管理運用 |
| 組織の作り方そのもの | 月々のツール代、契約更新日、支払いカード |
| | 障害・不審ログイン時の一次対応 |

**新設の根拠（2026-08-31 時点の滞留）**：アカウント・カード・権限の仕事が誰の持ち物でもないため止まっている。

| タスク | 状態 |
|---|---|
| 【入札】電子入札用ICカードを申し込む | 期限超過10日 |
| Adobeの支払いカードを切り替える | 期限超過8日 |
| 法人カード・アプラスカードが未到着―問い合わせ | 期限超過7日 |
| 虹、結HPのwp-adminログイン情報を用意する | 期限未設定・放置 |
| HP:お問い合わせ自動返信メールの設定 | 期限未設定・放置 |
| Adobeアカウントへの不審なログインメール | 次回発生時のみ対応 |

加えて、AIガタリは「**法人カード到着待ちが唯一のボトルネック**」と8/15に記録されている。情シスの不在が事業を1件止めている。
